Reporting a bug

If you are reporting a problem with a specific tool, a few details make it much faster to reproduce and fix:

  • Which tool you were using (e.g. JSON Formatter, JWT Decoder, CSV to JSON)
  • A short description of what happened versus what you expected
  • Your browser and operating system (e.g. Chrome 120 on Windows 11)
  • If it's safe to share, a small snippet of the input that triggered the issue

Please don't paste secrets. Every tool on this site runs entirely in your browser precisely so that sensitive data never leaves your device — so when you email a bug report, redact tokens, passwords, and personal data first. If a JWT or log is involved, the Log Redactor can strip the sensitive parts before you copy anything into a message.

Suggesting a tool

If there is a developer utility you wish existed here, send a suggestion. The roadmap is driven by what developers actually reach for day to day — not guesses. Tell me the workflow you're trying to speed up, and I'll see whether a tool fits the site's privacy-first, browser-only approach.

Reporting a content correction

The error reference and guides aim to be technically accurate, but software changes and mistakes happen. If you spot something wrong — an outdated default, an incorrect code example, a broken link — please tell me which page and what's off. Corrections are treated as a priority, because a reference is only useful if it's right.
